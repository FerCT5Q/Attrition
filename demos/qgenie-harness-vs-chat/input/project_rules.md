# Project reporting rules

- The report is for a non-technical leadership audience.
- Write the report in clear Spanish.
- Use the status spreadsheet for quantitative values.
- Use meeting notes to explain context, risks, and pending decisions.
- Do not treat a proposed date as an approved date.
- Do not invent causes, dates, owners, or completion percentages.
- Every risk must include a team and a next action when the sources provide
  them.
- Conflicting source values must be visible in the report.
- Keep the report concise: executive summary, status table, risks, decisions,
  and next actions.
- Use team names instead of personal names.
